# generate-smart-html

Turn a user's content into two portable artifacts: one self-contained HTML
file that looks sharp on screen, and a pixel-faithful US Letter PDF of the
same file — portrait or landscape, the user's call — rendered by headless
Google Chrome.

## When to Use

- The user wants a report, one-pager, dashboard snapshot, resume, invoice,
  or document rendered as a clean webpage AND a US Letter PDF
- The user asks for a portable / single-file / zero-dependency HTML output
- The user has an existing HTML file and needs a faithful US Letter PDF of it

## Hard Requirements

- **Single file, zero dependencies**: all CSS and JS inline, no CDN links,
  no external fonts or images (inline SVG / data URIs only)
- **US Letter fidelity**: every generated file ships an
  `@page { size: letter [landscape]; }` rule plus print CSS — orientation is
  decided at intake, and can be overridden at export time
- **Headless Chrome export**: the PDF comes from `scripts/export-pdf.sh`
  (Chrome's own renderer), never a screenshot or converter library

## Examples

### Example 1: data report, portrait

User says: "Generate an HTML report of these quarterly numbers that I can print"

Actions:
1. Intake per `workflow/intake/context-gathering.md` (audience, sections, orientation -> portrait)
2. Build one HTML file per `html/design/single-file.md` with inline SVG charts
3. Run `bash scripts/export-pdf.sh report.html portrait report.pdf`
4. Open the PDF; verify breaks and colors per `pdf/export/print-css.md`

Result: `report.html` (portable, works offline from file://) + `report.pdf` (US Letter portrait).

### Example 2: landscape comparison one-pager

User says: "Make a landscape one-pager comparing these three vendors, and give me a PDF"

Actions:
1. Intake confirms landscape and single-page target
2. Build with `@page { size: letter landscape; }` and `break-inside: avoid` on the table
3. Run `bash scripts/export-pdf.sh vendors.html landscape`

Result: one-page US Letter landscape PDF whose table never splits across pages.

## Troubleshooting

**PDF is blank or missing content**
Cause: JS-rendered content wasn't ready when Chrome printed.
Fix: use `--virtual-time-budget` (already set in `scripts/export-pdf.sh`); prefer static markup over runtime-rendered DOM for print targets.

**Backgrounds/colors missing in the PDF**
Cause: print rendering drops backgrounds unless told otherwise.
Fix: `print-color-adjust: exact` (see `pdf/export/print-css.md`).

**"no Chrome/Chromium found"**
Cause: export script couldn't locate a browser binary.
Fix: install Google Chrome, or pass the binary path via `CHROME_BIN=/path/to/chrome`.

## Success Signals

- `scripts/lint.sh` exits 0 after every ingest
- Generated HTML contains no `http(s)://` references and renders correctly from `file://`
- The exported PDF matches the on-screen design (colors, type, spacing) at the chosen orientation, with no clipped or orphaned content
- `log.md` grows by exactly one entry per session
